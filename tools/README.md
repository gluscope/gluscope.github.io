# tools/

Scripts that build the presentation layer of the site. Neither is needed to
*serve* the site -- everything they produce is committed. They exist so the work
can be re-applied and reviewed rather than being a one-off hand edit.

> **Important for whoever owns the page generator.** The `vis.html` files are
> machine-generated by a script that is not in this repository. Regenerating
> them overwrites everything `apply-site-shell.py` does. Either re-run that
> script after each regeneration, or fold the shell it applies (a stylesheet
> link, a `<div id="gs-nav">`, a `<main>` wrapper and two `<script type="module">`
> tags) into the generator itself, after which the script can be deleted.

## `patch-circuitsvis.py`

Vendors `circuitsvis@1.43.3` into `assets/` with one component replaced.

Two bugs in the upstream `ColoredTokensMulti` made the colour scale unreliable:

1. **The bounds went stale.** The positive/negative bounds were held in
   `useState` and initialised once on mount. Selecting a different channel
   recomputed the correct values but never pushed them into that state, so every
   channel after the first was drawn against the *previous* channel's scale.

2. **A literal `0` replaced the Reset button.** The button rendered as
   `defaultValue && <button/>`. When a channel is entirely negative the positive
   bound clamps to `1e-7`, and `(1e-7).toFixed(6) === "0.000000"` → `0` → falsy,
   so React printed the character `0`. In exactly the cases where the bounds were
   most likely to be stale, the control that would have fixed them was missing.

The replacement **derives** both bounds from the selected channel on every
render and presents them as read-only negative/positive bound labels. The values are by definition the
ones the old Reset button restored: per-channel column max/min, clamped to
±1e-7, rounded to 6 decimals. Because they are derived rather than stored, they
cannot go stale; because there is no input, they cannot be edited.

The bundle is patched rather than wrapped because the multi-channel hover
tooltip is only reachable from inside it -- circuitsvis exports `ColoredTokens`,
which does not accept tooltips.

**Token colours are unchanged** (red for negative, blue for positive). They are
exposed as `NEGATIVE_COLOR` / `POSITIVE_COLOR` near the top of the script; edit
those two lines and re-run to restyle the heat-map. The legend gradient follows.

The patch targets *minified* identifiers and is pinned to 1.43.3. Nine
assertions check every assumption before anything is written, so a version bump
fails loudly instead of half-applying.

```
python3 tools/patch-circuitsvis.py     # writes assets/circuitsvis-1.43.3-patched.js
```

The upstream download is cached at `tools/.circuitsvis-1.43.3.orig.js` and is
git-ignored; delete it to force a re-download.

## `apply-site-shell.py`

Wraps every `<model>/<layer>/<neuron>/vis.html` in the shared shell: the
stylesheet, the breadcrumb nav mount, and the shared heat-map loader -- replacing
the ~60 lines of near-duplicate JavaScript that were inlined into each page.

The generated content (headings, summary table, nested `<details>`,
`.circuit-viz` placeholders) is passed through **untouched** and restyled purely
from CSS. The script refuses to write a page whose content region has lost its
`.circuit-viz` placeholders or its `<h1>`.

It is idempotent: the shell is rebuilt each run and the content region is
recognised in both its original and already-wrapped form.

```
python3 tools/apply-site-shell.py --check   # report, write nothing
python3 tools/apply-site-shell.py           # apply
```

| --- | --- |
| `gluscope.css` | the whole design system: GitHub-style surfaces, gruvbox-blue accent, light + dark |

| `gluscope-viz.js` | lazy-loads and renders each heat-map |
